## When to use it

When the answer may take more than one line. It is the [field](../field/)'s box, grown: same line, same focus, same error, so the two line up in a form.

- A name, a number, a path: use an [input](../field/).

## Examples

### In a field

Three lines high before you type. In Chrome and Edge it grows with its text up to ten lines, then scrolls; in every browser the user can drag its height.

<Demo html={`
<div class="b-field" style="width: min(100%, 400px)">

  <textarea class="b-input" id="note" aria-describedby="note-hint"></textarea>
  <p class="b-field__hint" id="note-hint">Shown under the file name.</p>
</div>
`} />

## Accessibility

- The same as the [field](../field/#accessibility): a real `<label for>`, hint and error through `aria-describedby`.
- Growing with the text uses `field-sizing: content` ([MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/field-sizing)); where it is missing, the box keeps three lines and scrolls.

## In HTML

| Markup | Effect |
|---|---|
| `<textarea class="b-input">` | The input's box: three lines high, growing to ten where supported. |
| `aria-invalid="true"` | Red border. |
| `disabled` | The box fades. |

## In Preact

`Textarea` takes the `Field`'s ids and `aria-*` links, like `Input`.

```tsx
import { Field, Textarea } from '@beastui/preact';

<Field label="Description" hint="Shown under the file name.">
  <Textarea value={text} onInput={(e) => setText(e.currentTarget.value)} />
</Field>
```

| Prop | Type | Default | |
|---|---|---|---|
| `class` | `string` | | Extra classes, after `b-input`. |
| …the native `<textarea>` props | | | `value`, `onInput`, `rows`, `maxLength`, `disabled`… |
