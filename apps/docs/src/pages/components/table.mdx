# Table

<p class="docs-lead">Rows of things with the same fields: sort them, select some, act on them.</p>

## When to use it

For a list people compare or scan by column: files, orders, users.

- A nested list (folders): use a [tree](../tree/).
- A few settings: use fields, not a table.

## Live

- **Sort:** click a header for ascending, again for descending, a third time for the original order.
- **Select:** tick a box, or click anywhere in its cell. Shift+click selects every row between it and the last one clicked. Cmd+click (Ctrl+click on Windows) adds or removes one row.
- **Open:** a plain click on a row is the app's: here it opens the file.

## Plain

A native `<table>`: no component needed. One column takes the room left with `data-grow` and cuts its text with an ellipsis; numbers align right with `data-align="end"`.

## In Preact

BeastUI gives building blocks, not a data grid: you write the table, so any cell can hold anything. Three pieces do the work:

- `useSort` sorts the rows and remembers the column.
- `SortHeader` is a header cell you click to sort.
- `useSelection` remembers the selected rows and wires the checkboxes and the row clicks.

```tsx
import { Checkbox, SortHeader, compareText, useSelection, useSort } from '@beastui/preact';

const sort = useSort(files, {
  name: (a, b) => compareText(a.name, b.name),
  size: (a, b) => a.bytes - b.bytes,
});
// The ids in the order shown, so a Shift+click range follows the screen.
const selection = useSelection(sort.rows.map((t) => t.id));

<table class="b-table">
  <thead>
    <tr>
      <th data-select><Checkbox aria-label="Select all files" {...selection.allCheckbox()} /></th>
      <SortHeader column="name" sort={sort} grow>Name</SortHeader>
      <SortHeader column="size" sort={sort} align="end">Size</SortHeader>
    </tr>
  </thead>
  <tbody>
    {sort.rows.map((t) => (
      <tr key={t.id} {...selection.row(t.id, () => open(t))}>
        <td data-select><Checkbox aria-label={`Select ${t.name}`} {...selection.checkbox(t.id)} /></td>
        <td data-grow>{t.name}</td>
        <td data-align="end">{formatSize(t.bytes)}</td>
      </tr>
    ))}
  </tbody>
</table>
```

## API

### useSort

Sorts the rows by one column at a time and remembers which. Give it the rows and one ascending comparator per sortable column.

```ts
useSort(rows, compare, initial?)
```

| Returns | Type | |
|---|---|---|
| `rows` | `T[]` | A sorted copy. Equal rows keep their order. |
| `state` | `{ key, direction } \| null` | `direction` is `'ascending'` or `'descending'`. |
| `toggle(key)` | `(key) => void` | Ascending, descending, then the original order. Another column starts ascending. |
| `setState(state)` | | To set or clear the sort from elsewhere. |

Sorting on a server: ignore `rows`, read `state` and fetch.

### SortHeader

A header cell that sorts its column on click and shows the arrow.

| Prop | Type | Default | |
|---|---|---|---|
| `column` | `string` | required | The key this header sorts. |
| `sort` | what `useSort` returned | required | |
| `align` | `'start' \| 'center' \| 'end'` | `'start'` | `end` for long numbers, `center` for short values of one width (dates, durations). |
| `grow` | `boolean` | `false` | The column that takes the room left. |

### useSelection

Remembers the selected rows and gives the props for the checkboxes and the rows. Give it the ids in the order shown, so a Shift+click range follows the screen.

```ts
useSelection(ids, initial?)
```

| Returns | Type | |
|---|---|---|
| `checkbox(id)` | props | Spread on the row's `Checkbox`. |
| `allCheckbox()` | props | Spread on the header's `Checkbox`: mixed when some rows are selected. |
| `row(id, onOpen?)` | props | Spread on the `<tr>`: `data-selected`, Cmd+click, Shift+click, a click in the box's cell. A plain click calls `onOpen`. |
| `selected` | `ReadonlySet<Id>` | Every selected id. |
| `isSelected(id)` | `boolean` | |
| `setSelected(ids)`, `clear()` | | After a bulk action, for instance. |

### compareText

A comparator for text, the way people expect it: case and accents ignored, "File 2" before "File 10".

```ts
compareText(a: string, b: string): number
```

## The CSS contract

| Markup | Effect |
|---|---|
| `<table class="b-table">` | 36px rows (32 in `tool`), one line per cell, hairline dividers, tabular figures, a sticky header. |
| `data-grow` on a column's cells | Takes the room left and shrinks first, with an ellipsis. The table fits its box. |
| `data-align="end"` on a cell | Right-aligned: long numbers, so digits line up by place. |
| `data-align="center"` on a cell | Centred: short values of one width, like a date or a duration. |
| A `.b-btn` in a cell | The small control (24px, 20 in `tool`), so the row keeps air around it. |
| `data-select` on a cell | The narrow checkbox column. |
| `data-selected` on a `<tr>` | The hover tint, kept, and a bold edge on the left. |
| `aria-sort` on a `<th>` with a `<button class="b-table-sort">` | A sortable header and its arrow. |
| `--b-table-gap` | The gap between two columns, the same everywhere: 16px. |
| `--b-table-ground` | The header's fill. Set it to `var(--b-color-surface-card)` on a card. |

## Accessibility

- A native table: a screen reader moves by row and column and reads each cell with its header.
- A sortable header is a `<button>`, and only the sorted column carries `aria-sort` ([WAI-ARIA APG, sortable table](https://www.w3.org/WAI/ARIA/apg/patterns/table/examples/sortable-table/)).
- Each row's checkbox needs a name: `aria-label="Select Contract.pdf"`.
- Selected is a ticked box **and** an edge, never colour alone.
- Tab moves through the controls. Arrow keys between cells would be the [grid pattern](https://www.w3.org/WAI/ARIA/apg/patterns/grid/), not built.
- Shift+click and Cmd+click are mouse shortcuts; every row can also be ticked one by one with the keyboard.
- Cut text keeps its full value in `title`, so it shows on hover.
