# Modal

<p class="docs-lead">A box in front of the page, for a short task or a question. The page waits behind it.</p>

## When to use it

For something the user must finish or answer before going on: rename a file, confirm a deletion, choose export options.

- Longer content, read beside the page's context (a file's details, settings): use a [drawer](../drawer/).
- Something that only informs: a message in the page, not a modal. A modal stops the user.

## How it behaves

It is a native `<dialog>` opened with `showModal()`, so the browser brings most of it:

- the page behind is inert: no click, no Tab, no screen reader reaches it;
- the focus moves inside, to the first control (or the one with `autofocus`), and comes back to what opened it on close;
- **Escape**, a click on the backdrop or the close button close it;
- it sits above everything (the browser's top layer), with no `z-index` to manage.

Only the body scrolls: the title and the actions stay in view.

## In Preact

```tsx
import { Button, Modal } from '@beastui/preact';

const [open, setOpen] = useState(false);

<Modal
  open={open}
  onClose={() => setOpen(false)}
  title="Rename file"
  footer={<>
    <Button onClick={() => setOpen(false)}>Cancel</Button>
    <Button variant="primary" type="submit" form="rename">Rename</Button>
  </>}
>
  <form id="rename" onSubmit={rename}>…</form>
</Modal>
```

| Prop | Type | Default | |
|---|---|---|---|
| `open` | `boolean` | required | Shown or not. The app owns this state. |
| `onClose` | `() => void` | required | The user asked to close (Escape, backdrop, close button). Set `open` to false. |
| `title` | `ComponentChildren` | required | The heading, and the modal's accessible name. |
| `footer` | `ComponentChildren` | | Actions at the bottom, kept in view. Leave it out when there are none. |
| `closeLabel` | `string` | `'Close'` | The close button's name, for a screen reader. |

Escape is the browser's: the modal is already closed when `onClose` runs, so it can't be kept open from there. To protect unsaved work, ask before the user can lose it, not on close.

## Without Preact

The markup, and two lines of script: a `<dialog>` opens only by a method call.

```html
<dialog class="b-modal" aria-labelledby="rename-title">
  <header class="b-modal-head">
    <h2 class="b-modal-title" id="rename-title">Rename file</h2>
    <button class="b-btn" data-variant="quiet" data-icon type="button" aria-label="Close">…</button>
  </header>
  <div class="b-modal-body">…</div>
  <footer class="b-modal-foot">…</footer>
</dialog>
```

```js
openButton.addEventListener('click', () => dialog.showModal());
closeButton.addEventListener('click', () => dialog.close());
```

The click on the backdrop is not native in every browser yet (`closedby`, not in Safari): the Preact component adds it.
